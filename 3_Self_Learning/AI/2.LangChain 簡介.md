## 歷史背景

LangChain 是由 Harrison Chase 於 **2022 年 10 月**創建的開源框架，恰逢 ChatGPT 推出前夕。當時大型語言模型（LLM）剛開始展現強大能力，但開發者在構建實際應用時面臨許多挑戰。LangChain 迅速成為最受歡迎的 LLM 應用開發框架之一，並在 2023 年獲得大量投資，成立了 LangChain Inc. 公司。

## 解決的核心問題

LangChain 主要解決以下幾個問題：

**1. LLM 的局限性**

- LLM 本身是靜態的，只能基於訓練數據回答問題
- 無法訪問實時數據或外部資訊
- 缺乏記憶能力，無法在對話中保持上下文

**2. 應用開發複雜度**

- 將 LLM 整合到實際應用中需要大量重複性工作
- 缺乏標準化的開發模式和最佳實踐
- 難以管理多步驟的複雜工作流程

**3. 數據整合困難**

- 企業內部數據散落在各處（文檔、數據庫、API 等）
- 難以讓 LLM 有效利用這些私有數據

## 解決方案

LangChain 提供了幾個核心概念和工具：

**1. Chains（鏈）** 將多個組件串聯起來形成工作流程。例如：先從數據庫檢索信息，再用 LLM 生成回答，最後格式化輸出。

**2. Agents（代理）** 讓 LLM 能夠動態決定使用哪些工具來完成任務。例如，LLM 可以自主決定是否需要搜索網路、查詢數據庫或執行計算。

**3. Memory（記憶）** 提供多種記憶機制，讓對話能夠保持上下文，實現更自然的多輪對話。

**4. Tools（工具）** 豐富的工具集成，包括搜索引擎、API、數據庫、計算器等，擴展 LLM 的能力邊界。

**5. Retrieval（檢索）** 整合向量數據庫和檢索增強生成（RAG）技術，讓 LLM 能夠訪問大量外部知識庫和文檔。

**6. Prompts（提示詞管理）** 提供提示詞模板和管理機制，方便重用和優化提示詞。

## 實際應用場景

LangChain 使得開發者可以快速構建各種應用，例如智能客服機器人（能訪問公司知識庫）、文檔問答系統、代碼助手、數據分析工具等。它大幅降低了 LLM 應用開發的門檻，讓開發者能專注於業務邏輯而非底層實現細節。

值得注意的是，LangChain 生態系統現在包括 LangSmith（用於調試和監控）和 LangServe（用於部署），形成了完整的開發到生產的解決方案。

# 建立公司知識庫與 LangChain 訪問方式

## 一、建立公司知識庫的步驟

### 1. 收集和整理知識來源

首先需要確定知識來源，常見的包括：

- 內部文檔（Word, PDF, Markdown 等）
- 公司 Wiki 或內部網站
- 客服記錄和 FAQ
- 產品手冊、技術文檔
- 郵件記錄、會議紀要
- 數據庫中的結構化數據

### 2. 文檔處理與切分

將文檔轉換成 LLM 可以理解的格式：

python

```python
from langchain.document_loaders import PDFLoader, TextLoader, DirectoryLoader
from langchain.text_splitter import RecursiveCharacterTextSplitter

# 載入文檔
loader = DirectoryLoader('./company_docs/', glob="**/*.pdf")
documents = loader.load()

# 切分文檔（重要！因為文檔可能很長）
text_splitter = RecursiveCharacterTextSplitter(
    chunk_size=1000,  # 每段文字長度
    chunk_overlap=200  # 段落間重疊，保持上下文連貫
)
texts = text_splitter.split_documents(documents)
```

### 3. 生成向量嵌入（Embeddings）

將文本轉換成數字向量，這是實現語義搜索的關鍵：

python

```python
from langchain.embeddings import OpenAIEmbeddings

embeddings = OpenAIEmbeddings()
# 也可以使用開源模型，如 HuggingFace 的模型
```

### 4. 存儲到向量數據庫

選擇適合的向量數據庫：

**常用選項：**

- **Pinecone**：雲端託管，易於使用
- **Chroma**：輕量級，適合開發測試
- **Weaviate**：功能強大，支持混合搜索
- **Qdrant**：高性能，支持本地部署
- **FAISS**：Facebook 開源，適合本地使用

python

```python
from langchain.vectorstores import Chroma

# 創建向量數據庫
vectorstore = Chroma.from_documents(
    documents=texts,
    embedding=embeddings,
    persist_directory="./company_knowledge_base"
)
```

## 二、LangChain 訪問知識庫的方式

### 方法 1：基礎檢索問答（Retrieval QA）

python

```python
from langchain.chains import RetrievalQA
from langchain.chat_models import ChatOpenAI

# 初始化 LLM
llm = ChatOpenAI(temperature=0, model="gpt-4")

# 創建問答鏈
qa_chain = RetrievalQA.from_chain_type(
    llm=llm,
    chain_type="stuff",  # 將檢索到的文檔直接塞給 LLM
    retriever=vectorstore.as_retriever(search_kwargs={"k": 3})  # 檢索最相關的 3 段
)

# 提問
response = qa_chain.run("公司的休假政策是什麼？")
```

### 方法 2：對話式檢索（Conversational Retrieval）

支持多輪對話，帶記憶功能：

python

```python
from langchain.chains import ConversationalRetrievalChain
from langchain.memory import ConversationBufferMemory

# 設置記憶
memory = ConversationBufferMemory(
    memory_key="chat_history",
    return_messages=True
)

# 創建對話鏈
conversation_chain = ConversationalRetrievalChain.from_llm(
    llm=llm,
    retriever=vectorstore.as_retriever(),
    memory=memory
)

# 多輪對話
response1 = conversation_chain({"question": "公司有哪些福利？"})
response2 = conversation_chain({"question": "剛才提到的健康保險包含什麼？"})
```

### 方法 3：使用 Agent 進行智能檢索

讓 LLM 自主決定何時查詢知識庫：

python

```python
from langchain.agents import initialize_agent, Tool
from langchain.agents import AgentType

# 將知識庫包裝成工具
tools = [
    Tool(
        name="CompanyKnowledgeBase",
        func=qa_chain.run,
        description="用於回答公司政策、流程、產品相關問題。輸入應該是完整的問題。"
    )
]

# 初始化 Agent
agent = initialize_agent(
    tools,
    llm,
    agent=AgentType.ZERO_SHOT_REACT_DESCRIPTION,
    verbose=True
)

# Agent 會自動判斷是否需要查詢知識庫
response = agent.run("幫我查一下公司的報銷流程，然後總結成 3 個步驟")
```

### 方法 4：混合檢索策略

結合關鍵詞搜索和語義搜索：

python

```python
from langchain.retrievers import EnsembleRetriever
from langchain.retrievers import BM25Retriever

# 關鍵詞檢索器
bm25_retriever = BM25Retriever.from_documents(texts)

# 向量檢索器
vector_retriever = vectorstore.as_retriever()

# 混合檢索器
ensemble_retriever = EnsembleRetriever(
    retrievers=[bm25_retriever, vector_retriever],
    weights=[0.5, 0.5]  # 各佔 50% 權重
)

qa_chain = RetrievalQA.from_chain_type(
    llm=llm,
    retriever=ensemble_retriever
)
```

## 四、部署考量

### 安全性

- 實施訪問控制，不同員工訪問不同知識範圍
- 敏感信息需要特別標記和處理
- 記錄查詢日誌以便審計

### 維護更新

- 建立定期更新機制，保持知識庫時效性
- 實施版本控制，追蹤文檔變更
- 監控使用情況，優化常見問題的答案

### 性能優化

- 使用緩存減少重複查詢的成本
- 考慮使用專用的向量數據庫服務
- 批量處理大規模文檔更新

這樣建立的知識庫系統能夠讓 LLM 有效訪問公司內部知識，大幅提升回答的準確性和實用性。

# 是的！PostgreSQL 可以作為向量數據庫

PostgreSQL 通過 **pgvector** 擴展可以成為一個非常優秀的向量數據庫選擇，特別適合已經在使用 PostgreSQL 的企業。

## 一、為什麼選擇 PostgreSQL + pgvector？

### 優點

**1. 整合性強**

- 如果公司已經在使用 PostgreSQL，不需要額外維護另一個數據庫
- 可以將向量數據和業務數據存在同一個數據庫中
- 支持 JOIN 操作，結合結構化數據和向量搜索

**2. 成熟穩定**

- PostgreSQL 是久經考驗的企業級數據庫
- 完善的備份、恢復、權限管理機制
- 豐富的生態系統和社區支持

**3. 成本效益**

- 開源免費
- 可以本地部署，數據完全掌控
- 不需要為向量存儲支付額外的雲服務費用

**4. 功能豐富**

- 支持混合查詢（向量 + 傳統 SQL 過濾）
- 支持 ACID 事務
- 可以使用 PostgreSQL 的所有功能（觸發器、函數等）

### 限制

- 在超大規模場景（數億條向量）下，性能可能不如專門的向量數據庫
- 向量搜索的優化算法不如 Pinecone、Qdrant 等專業產品豐富

## 二、安裝和設置 pgvector

### 1. 安裝 pgvector 擴展

bash

```bash
# Ubuntu/Debian
sudo apt install postgresql-server-dev-all
git clone https://github.com/pgvector/pgvector.git
cd pgvector
make
sudo make install

# 或使用 Docker
docker run -d \
  -e POSTGRES_PASSWORD=password \
  -p 5432:5432 \
  ankane/pgvector
```

### 2. 在數據庫中啟用擴展

sql

```sql
-- 連接到數據庫後執行
CREATE EXTENSION vector;
```

### 3. 創建表結構

sql

```sql
-- 創建存儲向量的表
CREATE TABLE company_documents (
    id SERIAL PRIMARY KEY,
    content TEXT,
    metadata JSONB,
    embedding vector(1536),  -- OpenAI 的嵌入維度是 1536
    created_at TIMESTAMP DEFAULT NOW()
);

-- 創建向量索引以加速搜索
CREATE INDEX ON company_documents 
USING ivfflat (embedding vector_cosine_ops)
WITH (lists = 100);  -- lists 參數根據數據量調整
```

## 三、在 LangChain 中使用 PostgreSQL

### 完整示例

python

```python
from langchain.vectorstores.pgvector import PGVector
from langchain.embeddings import OpenAIEmbeddings
from langchain.document_loaders import DirectoryLoader
from langchain.text_splitter import RecursiveCharacterTextSplitter

# 1. 設置連接字符串
CONNECTION_STRING = "postgresql+psycopg2://user:password@localhost:5432/knowledge_base"

# 2. 初始化嵌入模型
embeddings = OpenAIEmbeddings()

# 3. 載入和處理文檔
loader = DirectoryLoader('./company_docs/', glob="**/*.pdf")
documents = loader.load()

text_splitter = RecursiveCharacterTextSplitter(
    chunk_size=1000,
    chunk_overlap=200
)
texts = text_splitter.split_documents(documents)

# 4. 創建 PGVector 存儲
vectorstore = PGVector.from_documents(
    documents=texts,
    embedding=embeddings,
    collection_name="company_knowledge",  # 相當於表名
    connection_string=CONNECTION_STRING,
)
```

### 查詢向量數據庫

python

```python
# 相似度搜索
query = "公司的休假政策是什麼？"
results = vectorstore.similarity_search(query, k=3)

for doc in results:
    print(f"內容: {doc.page_content}")
    print(f"元數據: {doc.metadata}")
    print("---")

# 帶分數的搜索
results_with_scores = vectorstore.similarity_search_with_score(query, k=3)

for doc, score in results_with_scores:
    print(f"相似度分數: {score}")
    print(f"內容: {doc.page_content}")
    print("---")
```

## 五、性能優化建議

### 1. 選擇合適的索引

sql

```sql
-- IVFFlat 索引（適合中等規模）
CREATE INDEX ON company_documents 
USING ivfflat (embedding vector_cosine_ops)
WITH (lists = 100);

-- HNSW 索引（更快但佔用更多空間，需要 pgvector 0.5.0+）
CREATE INDEX ON company_documents 
USING hnsw (embedding vector_cosine_ops);
```

### 2. 調整 lists 參數

python

```python
# lists 建議值：
# 行數 < 1M: lists = rows / 1000
# 行數 >= 1M: lists = sqrt(rows)

# 例如 100,000 行數據
lists = 100000 / 1000  # = 100
```

### 3. 定期維護

sql

```sql
-- 更新統計信息
ANALYZE company_documents;

-- 重建索引（如果數據變化很大）
REINDEX INDEX company_documents_embedding_idx;

-- 清理空間
VACUUM company_documents;
```

### 4. 連接池配置

python


## 六、完整應用示例

python

```python
from langchain.chains import RetrievalQA
from langchain.chat_models import ChatOpenAI
from langchain.vectorstores.pgvector import PGVector
from langchain.embeddings import OpenAIEmbeddings

# 設置
CONNECTION_STRING = "postgresql+psycopg2://user:password@localhost:5432/knowledge_base"
embeddings = OpenAIEmbeddings()

# 連接現有知識庫
vectorstore = PGVector(
    collection_name="company_knowledge",
    connection_string=CONNECTION_STRING,
    embedding_function=embeddings,
)

# 創建檢索器
retriever = vectorstore.as_retriever(
    search_type="mmr",  # 使用 MMR 增加多樣性
    search_kwargs={
        "k": 5,
        "fetch_k": 20,
        "filter": {"department": "HR"}  # 可選的元數據過濾
    }
)

# 創建問答鏈
llm = ChatOpenAI(temperature=0, model="gpt-4")
qa_chain = RetrievalQA.from_chain_type(
    llm=llm,
    chain_type="stuff",
    retriever=retriever,
    return_source_documents=True  # 返回來源文檔
)

# 查詢
result = qa_chain({"query": "公司的年假有幾天？"})
print(f"回答: {result['result']}")
print(f"\n來源文檔:")
for doc in result['source_documents']:
    print(f"- {doc.metadata}")
```

## 七、何時選擇 PostgreSQL vs 專門的向量數據庫？

### 選擇 PostgreSQL 的情況：

- 已經在使用 PostgreSQL
- 數據規模在百萬級別以下
- 需要結合結構化數據查詢
- 希望簡化架構，減少維護成本
- 需要強大的事務支持

### 選擇專門向量數據庫的情況：

- 數據規模超大（千萬、億級）
- 需要極致的向量搜索性能
- 需要更複雜的向量搜索算法
- 願意為性能支付額外成本

對於大多數企業級應用，PostgreSQL + pgvector 是一個非常實用且成本效益高的選擇！
